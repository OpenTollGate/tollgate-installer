# UI language: the catalogue, the picker, and the precedence

The wizard renders every user-facing string from a catalogue. This document is the
contract: which languages ship, how a request picks one, and what a contributor has
to do to add a string or a locale.

- `internal/i18n/locales/*.json` — the catalogues (one file per written language).
- `internal/i18n/catalogue.go` — which of the operator's requested languages have
  real text, which fall back to English and why, and the `T`/`Merge` accessors.
- `internal/i18n/resolve.go` — the per-request decision.
- `internal/app/index.html` — keys (`data-i18n="…"`) and the `t('…')` calls; no
  English prose.
- `internal/app/i18n_surface.go` — injects the decision and the merged catalogue
  into the page.

## The one rule

**A string a human reads comes from a catalogue, never from the markup or from a Go
literal.** `index.html` ships keys and the catalogue ships text. This is enforced,
not requested:

| guard | file | what it catches |
| --- | --- | --- |
| `TestNoStringIsRenderedOutsideTheCatalogue` | `internal/app` | a new `<p>`/`<label>`/`<button>` with English prose and no key |
| `TestEveryDataI18nKeyExists` | `internal/app` | `data-i18n="typo.key"` that no catalogue defines (renders the key name) |
| `TestEveryTKeyExists` | `internal/app` | `t('typo.key')` in the script — the same defect, invisible to an attribute scan |
| `TestEveryCatalogueKeyIsRendered` | `internal/app` | a key translated forever that nothing renders (dead key or half-applied rename) |
| `TestEveryCatalogueHasExactlyTheReferenceKeys` | `internal/i18n` | a locale missing a key, or carrying one `en.json` does not define |
| `TestEveryCatalogueKeepsItsPlaceholders` | `internal/i18n` | a translation that drops `{ip}` (the value then silently disappears) |
| `TestEveryCatalogueIsNonEmptyAndNotJustEnglishCopy` | `internal/i18n` | a locale that is English with a different filename |
| `TestNoOrphanCatalogueFile` | `internal/i18n` | a `locales/xx.json` that no shipped tag renders |

A string that genuinely must not be translated declares that **at the string**, with a
reason: `data-i18n-skip="product name"`. The exemption is deliberately not a list in
the test — a list is inherited by the next untranslated string, an attribute is not.

## The precedence (and why this order)

```
1. saved explicit choice (cookie tollgate_i18n)
2. Accept-Language header  (q-values honoured, browser order respected)
3. IP country              — TIEBREAKER ONLY
4. English
```

1. **Saved choice first.** A picker that lost to `Accept-Language` would reset on
   every navigation: the user picks German, the header says `en-US`, the next page is
   English again. The saved choice is the only signal that is a *decision* rather than
   a *guess*, so it outranks everything.
2. **`Accept-Language` second,** with q-values honoured and the browser's order
   respected. Matching is: full tag (`de-AT`, `pt-BR`), then region→script for Chinese
   (`zh-TW` → `zh-Hant`, because those regions imply Traditional), then
   language+script (`zh-Hans-CN` → `zh-Hans`), then the base language (`de-AT` → `de`).
3. **IP country is a tiebreaker, never a decision.** The original request asked for
   IP-based detection; it does not work for this job:
   - IP geolocation yields a **country**, not a language. Belgium, Switzerland,
     Canada, India, Nigeria and South Africa all break the country→language mapping.
   - The installer is normally reached over the operator's **LAN**, so the client is
     `192.168.x.x` and there is nothing to geolocate. `clientCountry` returns `""`
     for loopback/private/link-local addresses for exactly this reason.
   - A VPN or CGNAT makes even the public-IP case unreliable.

   So it can only break a tie between two variants of a language we ship both of
   (e.g. `pt-PT` vs `pt-BR`). It must never override an explicit header: a German
   speaker with a `de-DE` browser behind a Spanish-exit VPN gets German.

   No geo database ships with the binary. `geoResolver` is a package-level hook that
   returns `""` by default — bundling a country DB adds megabytes to a binary that is
   `curl|bash`'d onto a router, and calling a public geo API would leak the operator's
   address off their own LAN for the weakest signal in the chain.
4. **English last.** It is also the language the UI was written in, so a missing key
   degrades to the sentence we shipped rather than to a blank.

The rung is decided **once, server-side, per request** (`handleIndex`), and the result
is written into the markup (`<html lang dir>`) as well as the payload. A browser-side
decision would disagree with the first paint, so an RTL reader would see a frame of
LTR layout.

## What ships, and what deliberately does not

The operator asked for the 21 most-spoken languages. Shipping a locale we have no
text for is worse than not shipping it: the picker would offer "मराठी", the user would
choose it, and the wizard would answer in English — which reads as a *broken
translation*, not as a *missing one*. So a tag is selectable only when it has a real
catalogue, and every other requested tag is recorded in `requestedLanguages` as an
explicit fallback-to-English **with the reason attached**.

Shipped: `en`, `zh-Hans`, `zh-Hant`, `es`, `fr`, `ar`, `pt`, `ru`, `id`, `de`, `ja`,
`vi`, `tr`, `it` (14 catalogues).

Fallback to English, with the reason recorded in `catalogue.go`: `hi`, `bn`, `ur`,
`pcm`, `mr`, `te`, `ta`, `wuu`. These are languages where a translation written
without native review would read as machine output (or, for `pcm` and `wuu`, where
there is no settled written UI convention at all). An honest catalogue beats a
doubtful one; each entry says why rather than leaving a gap someone has to rediscover.

`ar-EG` renders from the `ar` catalogue — regional Arabic variants share the written
register. `zh-Hant` does **not** reuse `zh-Hans`: the script differs, not just the
region, and a single `zh` would be wrong for Taiwan, Hong Kong and much of the
diaspora.

## RTL

`ar` (and `ur`, when it ships) get `dir="rtl"` on `<html>`, written into the markup at
render time. Mirrored layout is a separate pass from translation — `index.html` has a
`[dir="rtl"]` block covering text alignment, the password-toggle reserve, the range
readout, the disclosure arrows, the direction icon and error borders.

`e2e/i18n.spec.mjs` measures this rather than trusting the stylesheet: it asserts the
computed direction is `rtl`, the body alignment is right/start, and that the password
field's left padding (the toggle's reserve) is larger than its right — then asserts the
opposite on the English page, so the test cannot pass against a page that ignores
direction.

## Adding a string

1. Add the key + English text to `internal/i18n/locales/en.json`.
2. Use it in `index.html`: `data-i18n="key"` on the element, or `t('key')` (and
   `t('key', {name: value})` for interpolation) in the script.
3. Add the same key to every other catalogue — `TestEveryCatalogueHasExactlyTheReferenceKeys`
   fails until you do. If you cannot translate it, omit the key: a missing key
   falls back to English per key, and no test penalises an omitted one.

Interpolation takes `{name}` placeholders. `t()` substitutes each, so a translation may
reorder them freely ("{ip} selected" vs "Sélectionné : {ip}") without touching the call
site. `TestEveryCatalogueKeepsItsPlaceholders` requires every placeholder the English
value has.

## Adding a locale

1. Add `internal/i18n/locales/<tag>.json` with **exactly** the keys in `en.json`.
2. Add an entry to `requestedLanguages` in `catalogue.go` with `Catalogue: "<tag>"`.
   If you cannot produce a credible translation, add it with `FallbackWhy` instead —
   that is an accepted outcome, not a failure.
3. Run `go test ./internal/i18n/ ./internal/app/`; the lints will tell you what is
   missing.
4. Capture the screenshot: `WIZARD_URL=… npx playwright test i18n.spec.mjs` writes
   `e2e/screenshots/wizard-<tag>.png`.

## Running the acceptance gate

```sh
go build -o /tmp/tg-wiz . && /tmp/tg-wiz -port 8123 &
go test ./internal/i18n/ ./internal/app/                    # catalogue + surface lints
WIZARD_URL=http://127.0.0.1:8123 npx playwright test i18n.spec.mjs
```

The Playwright spec renders `en`, `de` and `ar`, asserts the payload reached the page,
and writes one screenshot per locale. Note that `page.setExtraHTTPHeaders` **cannot**
override `Accept-Language` — the browser builds that header itself. Use the per-context
`locale` option; a header-based spec silently runs in the default locale and passes
any assertion about English.
